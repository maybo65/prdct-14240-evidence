=== 3. The deny verdict comes ONLY from a live guard endpoint — no offline/local deny exists ===
scanner/internal/client/evalute.go
  210: guardUrl, _ := url.JoinPath(c.baseURL, "guard", "evaluate", "v1", c.apiKey, request.Source.String())
  184: if response.Action == "block" { ... }          # block ONLY ever comes from the server response body
  144: return c.failOpen(FailOpenInvalidRequest, ...)  # nil request      → allow
  158: return c.failOpen(FailOpenEndpointUnreachable, ...) # unreachable  → allow

  180: return c.failOpen(FailOpenResponseParseFailed, ...) # unparseable  → allow
  252-255: func (c *GenericEvaluateClient) failOpen(...) { ... Action:"allow" ... }

  -> Every failure mode FAILS OPEN (allow). A runner with no reachable guard endpoint CANNOT produce a real deny.
     The only network-free block (sanction.forceBlockReason, hooks.go ~390) is MCP server-identity ambiguity under
     --mcp-guard-hooks, NOT a content/prompt deny. => a macOS deny-through-chain run REQUIRES a reachable guard
     endpoint returning {"action":"block"} + its api-key. A stub/mock host returning "block" is an automatic-fail
     shortcut (testing-standard) and is NOT used.
